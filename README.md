# NMNB 연구 스크럼 봇

Discord에서 연구 구성원의 스크럼을 정해진 시간 동안 수집하고, 작성자별 원문을 하나의 Notion 보고서에 취합하는 봇입니다.

## 동작 방식

1. 서버 관리자가 연구 구성원을 수집 대상에 등록합니다.
2. 예약된 시각에 등록된 사람에게 연구 스크럼 작성 DM을 보냅니다.
3. 구성원은 DM의 버튼을 눌러 연구 내용을 제출합니다.
4. 마감 시각까지 받은 답변만 작성자별로 취합합니다.
5. 보고서를 Notion에 저장하고 Discord 보고 채널에 링크를 전송합니다.

수집 시작 전이나 마감 이후에 제출한 답변은 저장하지 않습니다. 이전 수집 기간의 버튼도 사용할 수 없습니다. 마감 전에는 같은 버튼으로 자신의 답변을 수정할 수 있습니다.

연구 스크럼 양식은 [templates/research-scrum.md](templates/research-scrum.md) 하나를 사용합니다. 새 입력창에도 같은 양식이 기본으로 채워집니다.

## 요구 사항

- Node.js 18 이상
- Discord 봇 토큰
- Notion Integration 토큰
- Notion에서 보고서를 저장할 부모 페이지 또는 데이터 소스

## 설치

```bash
npm install
```

[.env.example](.env.example)을 복사해 `.env`를 만들고 값을 입력합니다.

```env
DISCORD_TOKEN=
REPORT_CHANNEL_ID=
DISCORD_GUILD_ID=

NOTION_TOKEN=
NOTION_PARENT_PAGE_ID=
NOTION_DATA_SOURCE_ID=
NOTION_TITLE_PROPERTY=Name
NOTION_OUTPUT_URL=

DATA_DIR=./data
PORT=3000
```

### Discord 설정

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 애플리케이션과 봇을 만듭니다.
2. OAuth2 URL Generator에서 `bot`, `applications.commands` 범위를 선택해 서버에 초대합니다.
3. 봇에 보고 채널 보기와 메시지 전송 권한을 부여합니다.
4. Discord 개발자 모드에서 보고 채널 ID를 복사해 `REPORT_CHANNEL_ID`에 입력합니다.
5. `DISCORD_GUILD_ID`는 선택 사항입니다. 입력하면 해당 서버와 보고 채널이 일치하는지 시작할 때 검사합니다.

이 봇은 버튼과 입력창으로만 답변을 받으므로 Message Content Intent는 필요하지 않습니다.

### Notion 설정

1. Notion에서 Integration을 만들고 토큰을 `NOTION_TOKEN`에 입력합니다.
2. 보고서를 저장할 페이지 또는 데이터베이스를 Integration과 공유합니다.
3. 일반 페이지 아래에 저장하려면 `NOTION_PARENT_PAGE_ID`만 입력합니다.
4. 데이터베이스에 저장하려면 `NOTION_DATA_SOURCE_ID`만 입력하고 실제 제목 속성 이름을 `NOTION_TITLE_PROPERTY`에 입력합니다.
5. Discord에 항상 같은 데이터베이스 주소를 표시하려면 `NOTION_OUTPUT_URL`에 그 주소를 입력합니다. 비워 두면 생성된 개별 페이지 주소를 표시합니다.

`NOTION_PARENT_PAGE_ID`와 `NOTION_DATA_SOURCE_ID`는 동시에 입력할 수 없습니다. URL 전체가 아닌 ID를 입력합니다.

## 실행

```bash
npm start
```

개발 중 파일 변경 시 자동 재시작하려면 다음을 사용합니다.

```bash
npm run dev
```

봇은 시작할 때 설정된 서버에 슬래시 명령어를 등록합니다.

## 명령어

모든 명령어는 Discord의 서버 관리 권한이 있는 사용자만 실행할 수 있습니다.

| 명령어 | 설명 |
| --- | --- |
| `/대상추가 사용자:@사용자` | 다음 예약부터 연구 스크럼 DM을 받을 사람 등록 |
| `/대상삭제 사용자:@사용자` | 대상 삭제 및 기존 DM 버튼 무효화 |
| `/대상목록` | 등록된 대상 확인 |
| `/알림설정 요일:일 시간:20:00` | DM 발송 요일과 시각 설정 |
| `/마감설정 요일:일 시간:23:00` | 수집 마감 및 Notion 보고서 생성 시각 설정 |
| `/알림확인` | 일정, 대상 수, 제출 수 확인 |
| `/수집시작` | 현재 열려 있는 수집 기간 안에서 DM 재발송 |
| `/임의시작 유효시간:180` | 지금부터 지정한 시간 동안 새 수집을 열고 DM 발송 및 채널 공지 |
| `/임의마감` | 현재 수집을 즉시 닫고 Notion 보고서 생성 및 채널 공지 |
| `/보고서생성` | 현재 수집을 닫고 받은 답변으로 즉시 정식 보고서 생성 |
| `/테스트전송` | 관리자 본인에게 10분 유효한 테스트 DM 발송 |
| `/알림끄기` | 예약 DM, 자동 보고서 생성, 현재 수집을 모두 중지 |

요일은 `일` 또는 `월,수,금` 형식으로 입력하고 시간은 한국 시간 기준 24시간제 `HH:mm` 형식을 사용합니다.

예시:

```text
/알림설정 요일:일 시간:20:00
/마감설정 요일:일 시간:23:00
/대상추가 사용자:@홍길동
```

위 설정은 일요일 20시에 DM을 발송하고, 일요일 23시까지 받은 답변으로 보고서를 만듭니다.

## 연구 스크럼 항목

- 연구 목표와 핵심 질문
- 진행한 연구
- 주요 결과와 근거
- 문제와 위험 요소
- 다음 연구 계획
- 공유·결정 사항

답변은 요약하거나 재작성하지 않고 작성자별 원문 그대로 저장합니다. 응답자와 미응답자는 Notion 보고서의 응답 현황에 기록됩니다.
수집 시작은 보고 채널에 공지됩니다. 보고서가 생성되면 Notion 링크와 취합 본문도 같은 채널에 게시되며, Discord 메시지 길이를 넘는 본문은 `research-scrum.txt` 파일로 첨부됩니다.

## 테스트

외부 서비스에 연결하지 않는 단위 테스트:

```bash
npm test
```

Discord와 Notion을 실제로 연결하는 테스트는 봇 실행 후 `/테스트전송`을 사용합니다. 명령을 실행한 관리자에게 테스트 DM이 오며, 10분 안에 제출하면 `[TEST]` 연구 스크럼이 Notion에 저장됩니다. 정기 수집 데이터에는 영향을 주지 않습니다.

## 저장과 배포

`DATA_DIR`에는 일정, 수집 대상, 제출 원문과 최근 보고서 기록이 저장됩니다. Railway나 Render처럼 파일 시스템이 초기화될 수 있는 환경에서는 `DATA_DIR`을 영구 디스크 경로로 지정해야 합니다.

민감한 값이 포함된 `.env`와 수집 데이터가 들어 있는 `data/`는 Git에서 제외됩니다. 동일한 `DATA_DIR`을 여러 봇 프로세스가 동시에 사용하지 마세요.

HTTP 상태 확인 엔드포인트는 `PORT`에서 동작하며 Discord 연결과 런타임 준비가 완료되면 `200 OK`, 준비되지 않으면 `503 NOT READY`를 반환합니다.

## 문제 해결

- 명령어가 보이지 않으면 봇을 `applications.commands` 범위로 초대했는지 확인합니다.
- DM 전송 실패 대상은 서버 가입 상태와 개인 DM 허용 설정을 확인합니다.
- Notion 저장 실패는 Integration 공유 권한, 저장 위치 ID, 제목 속성 이름을 확인합니다.
- 보고서 생성에 실패하면 제출 원문을 유지합니다. 설정을 고친 뒤 `/보고서생성`으로 다시 시도할 수 있습니다.
